# Contributing

Open a pull request with the behavior or measurement you are changing and a reproduction command. Run the qualification and both native controls from the README. Keep generated tasks, model credentials, private issues, answer keys for sealed cases, and run logs out of the repository.

For a new fixture, show the starting symptom, the actual runtime route, a reference repair, a rejected unchanged submission, an inactive-path control, a valid alternative when applicable, and preservation checks. State what each disclosed hint reveals. Document verifier setup failures separately from product failures.

For a scoring change, include a concrete receipt or small outcome grid that distinguishes the old and new behavior. Record when a fixture change affects comparability. Pin the repository commit and assignment manifest in reported runs.

The main branch uses pull requests, a current approving review, resolved conversations, and the three Calibration workflow checks. The versioned ruleset is in [`.github/rulesets/main.json`](.github/rulesets/main.json). Use squash merges.
